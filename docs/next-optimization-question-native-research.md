# Trade Nothing 研究方向闭环：本轮优化基准与验收目标

> 状态：研究方向闭环基准；当前 P0/P1 定义见 `research-kernel-v0.15.md`
> 日期：2026-08-10
> 入口：`-deepthink2`
> 产品终点：Deep Research Report；不建设后续投资决策或执行流程

## 1. 本轮唯一目标

把系统从“问题清单驱动、crux 作为兼容审计副轨”推进为真正的**原始问题驱动研究循环**：

```text
原始问题
  -> 待回答问题（Research Agenda）
  -> 可质证的研究方向/论点
  -> 搜索、证据与双边质证
  -> 阶段判断
       ├─ 当前方向足以回答
       ├─ 当前方向仍需继续挖掘
       └─ 反证/盲点导出新观点
  -> 改写答案与下一轮优先级
  -> Deep Research Report
```

crux、比较轴、因果链、市场机制、候选路径和风险路径都只是完成这条循环的工具。它们不能
反过来把研究变成填表、晋级或等待“状态收敛”。

## 2. 三层研究对象

### 2.1 原始问题与 Agenda

- 原始问题定义用户最终希望解释和判断什么；
- Agenda 把它拆成 4—8 个可回答的问题，覆盖事实、原因、市场机制、产业增量、具体载体、
  价格/筹码、风险与前瞻盲点；
- Agenda 拥有调度、研究预算建议和报告时点；已回答的问题不得因 crux 未收敛而重派。

### 2.2 研究方向/论点

研究方向是围绕 Agenda 问题提出的可质证命题或路线，例如：

- `FACT_ROUTE`：某个时间、状态或身份事实由哪条来源路线建立；
- `CAUSAL_CLAIM`：延期、工程结果或产业变化的核心原因；
- `MARKET_MECHANISM`：事件如何经稀缺性、预期差和资金偏好传导；
- `CANDIDATE_PATH`：谁有事件弹性、谁获得真实经济增量、谁只是概念映射；
- `PRICING_CLAIM`：回调、成交、筹码与事件预期是否已被计价；
- `RISK_PATH`：失败、替代、延迟或拥挤交易如何让建议失效；
- `COMPARISON_AXIS`：多条机会路径应按什么承重变量比较；
- `CRUX`：会改变主答案、候选顺位或失效条件的承重方向。

方向必须链接回 Agenda 问题，并写明：命题、为什么重要、最低成本判别测试、证据、最强
反例和仍缺的判别信息。

### 2.3 证据

正式证据先进入统一 `evidence_items`，再由问题答案、研究方向、CandidateMap 或兼容 crux
引用。同轮引用只能绑定同一角色真实提交且通过 URL、来源和日期校验的 `evidence_id`。

这解决两个问题：普通事实不必伪装成 crux 才能被引用；同一来源也不能复制、改写后“洗成”
另一条证据。没有有效证据的洞察仍可保留，但必须标为 `INFERENCE / HYPOTHESIS`。

## 3. 每轮只做三种研究判断

对每个选中方向记录：

- `SUPPORTED`：当前证据更支持该方向；
- `CHALLENGED`：当前证据削弱或推翻该方向；
- `UNRESOLVED`：关键判别信息仍缺失或证据冲突。

同时选择下一研究动作：

- `ANSWER`：方向已足以形成有边界答案，或虽被推翻但可以明确回答“不成立”；
- `CONTINUE`：方向仍重要且下一项判别测试有信息价值；
- `OPEN_NEW_DIRECTION`：原方向被反证、异常或盲点改写，形成一个更值得检验的新观点。

这六个词是**研究记录，不是状态机**：没有晋级、审批、候选权限、持仓权限或自动执行；下一
轮可以基于新证据重判。确定性代码只校验证据绑定、记录历史并重排注意力，不代替研究者判断。

## 4. crux 的正确位置

crux 不是“可有可无的审计装饰”，也不是控制研究终止的根对象。它是研究方向中满足以下条件
的承重子类：

1. 结论、候选排序或条件性建议会因其真伪发生实质变化；
2. 存在能区分正反解释的可观察测试；
3. 值得 Detective/Inquisitor 对称质证；
4. Judge 只审核它的证据归属和冲突，不替 Agenda 决定是否继续研究。

兼容版本仍保存 crux signal/convergence 供归档审计，但其数值不能覆盖问题答案、研究方向判断
或报告交付。后续是否取消“每轮固定 Judge/至少两个兼容 crux”，只能在独立的执行器迁移中
处理；本轮不为此再造一套 review-mode 生命周期。

## 5. 调度与机会挖掘原则

每轮最多选择 3 个问题和 4 个相关研究方向，优先级依次考虑：

1. 是否阻断当前答案或条件性建议；
2. 是否为新出现且会改写结论的观点/盲点；
3. 决策影响和当前争议程度；
4. 最低成本判别测试是否清晰；
5. crux 链接只用于承重质证和最后的同级排序。

研究不能只做否定。若原方向失败，必须区分：

- 失败本身已经回答问题；
- 仍缺关键证据，应继续；
- 失败揭示了替代机制、二阶受益者、稀缺性变化、价值转移或反向风险，应建立新方向。

新观点允许先以假说进入，但必须说明其来源、会改变什么、最强替代解释和判别测试。具名候选
可以作为线索保存；正式事实和条件性结论仍受证据边界约束。

## 6. 报告产品形态

Deep Research Report 正文按用户问题组织：

1. 当前答案与边界；
2. 哪些研究方向成立、被挑战或仍未决；
3. 哪些反证/盲点产生了新观点，以及它如何改变原判断；
4. 市场运行逻辑、产业增量、具体载体、价格/筹码；
5. 条件性建议、触发、失效和剩余最高价值验证。

证据账本、crux signal、隔离收据和兼容状态只放审计附录。工程完成度、轮数、FORMAL 标签和
support score 不得替代研究质量。

## 7. 明确边界

本 Skill 止于研究报告。本轮及后续默认均不建设或触发：

- Thesis、Decision、CandidateScreen 晋级、订单、仓位、组合、审批；
- 自动续研、提醒、监控、发布、跨产品 handoff；
- 目标价、收益率、成功率伪精确值或仓位模型；
- 用测试通过、状态收敛或固定回放冒充 Alpha、机会召回或真实产品价值。

若用户以后明确要求上述能力，应先建设独立产品合同并重新授权；不能让本 Skill 预先替后续
流程做决定。

## 8. 研究方向闭环的历史实施清单

> 以下“P0/P1”是方向闭环当时的实施批次，不再代表当前优先级。当前 P0 是研究内核正确性
> 修复，当前 P1 是效率与报告价值验收，详见 `research-kernel-v0.15.md`。

### 阶段 A：研究对象与证据

- Research Agenda v3 增加 `research_directions` 与 `evidence_items`；
- 新 frame 可显式提供方向；旧 frame 自动把 crux 投影为承重方向，并为未覆盖问题建立兼容
  研究路线；
- 同轮 `evidence_id` 精确绑定问题和方向，旧 `crux_evidence / crux_attacks` 保持只读兼容；
- 每个方向保存判断历史、最强反例、未决问题与下一研究动作。

### 阶段 B：调度、Agent 与报告

- 调度同时派发问题和方向；新观点/高影响未决方向可提升相关问题优先级；
- Detective/Inquisitor 必须输出方向判断，并可从反证生成 `new_research_directions`；
- 控制层识别 `NEW_VIEWPOINT_OPENED` 与 `RESEARCH_DIRECTION_REQUIRES_CONTINUATION`，但额外
  轮次仍需显式授权；
- 报告展示方向判断、新观点来源和统一证据账本。

### 阶段 C：朱雀三号回放

固定同一组问题与证据，至少验证三条路径：

1. 工程/时间方向被支持，形成阶段答案；
2. “首个民营回收即最高稀缺性”方向被先发事实挑战，需要继续判断市场叙事；
3. 反证产生“市场可能交易民营商业闭环而非全国首次”的新方向，并在下一轮优先于普通补证。

回放只验证方法行为，不能声称当下事实、股票机会或 Alpha 已被验证。

## 9. 本轮完成标准

同时满足以下条件才算完成：

1. 原始问题、Agenda、研究方向、证据和报告形成可追溯闭环；
2. 普通证据无需借 crux 即可正式绑定问题和方向；
3. crux 被建模为承重研究方向，能影响质证与注意力，但不控制报告交付；
4. 每轮能明确记录“回答、续挖、新观点”，新观点能进入下一轮调度；
5. 朱雀回放覆盖支持、挑战、产生新观点三种结果；
6. 旧 payload 与归档运行保持可读，全部离线测试通过；
7. 报告止于研究建议，没有任何未授权的后续流程或状态扩张；
8. 方法身份更新后仍标记为未完成真实盲评，不能以工程验收宣称产品效果。

本基准取代此前“Question-native = 可选 crux + 条件 Judge”的单一优化叙事。角色调用优化仍
有价值，但它必须服从研究挖掘闭环，不能成为产品目标本身。
