# Trade Nothing v0.15 产品重置基准（历史阶段文档）

> 本文冻结第一次“发现优先”修复，现已由
> [`topic-led-research-product.md`](topic-led-research-product.md) 取代为当前产品基准。
> 其中强制大胆假说和 Opportunity Brief 终点只保留为历史决策，不再代表默认产品。

状态：`IMPLEMENTATION_IN_PROGRESS / UNBENCHMARKED_METHOD_CHANGE`
基准案例：朱雀三号遥二主题研究（证据截止 2026-08-07）
目的：冻结产品哲学、边界、目标形态和验收标准，防止继续用流程与状态补丁代替机会发现。

## 1. 为什么重置

v0.14 已证明自己能约束引用、反证、运行恢复和候选晋级，但朱雀三号运行暴露了产品错位：

- 五轮、十九条有效引用可以形成 `FORMAL` 报告，却没有形成可定价的具体候选；
- 抽象交易机制被自动写成 OpportunitySeed，随后因没有 ticker 无法绑定价格；
- 候选身份冻结后，补证任务不能再绑定超捷股份或斯瑞新材，只能以
  `SOURCE_EXHAUSTED` 结束；
- 系统优化了“状态是否合法”，没有优先回答“市场会怎样交易、资金会选谁”；
- 尚未建设的 Thesis、Decision、交易和组合流程反向侵入了研究 Skill 的设计。

因此，本次不是放宽一个闸门，而是重设主产品。

## 2. 三条产品宪法

### 2.1 发现是主产品，验证是按需工具

默认目标是发现主题中的具体市场机会：现实变化、非共识机制、资金传导、证券载体、
价格与筹码、催化和失效条件。证据审计负责约束表达和集中质证，不负责在发现之前
消灭候选。

### 2.2 严格性后置，逻辑诚实全程存在

发现阶段允许大胆假说、单一来源和未完全证实的映射，但必须标注为
`FACT / SINGLE_SOURCE / INFERENCE / HYPOTHESIS`，并给出最强替代解释与最低成本验证动作。
准备提升候选可信度时，才要求更严格的经济暴露、定价、催化、筹码和反证核查。

### 2.3 Skill 止于 Opportunity Brief

范围内：公开数据研究、主题与产业链地图、市场运行逻辑、具体证券池、条件性 setup、
风险与证伪、研究注意力排序、Opportunity Brief。

范围外：Thesis 创建、Decision 审批、模拟或实盘交易、订单、仓位、组合、归因、提醒、
发布审批和跨产品 handoff。代码库中的旧实现只作历史兼容，不进入默认产品合同。

## 3. 目标用户任务

输入一个主题、事件、行业变化或公司问题后，用户应在报告第一页得到：

1. 发生了什么；
2. 市场可能如何理解和交易；
3. 资金可能选择哪些具体证券；
4. 哪些是事件弹性，哪些可能获得真实经济增量；
5. 当前最值得继续研究或条件性博弈的 1—3 个 setup；
6. 每个 setup 的触发、时间窗、失效条件、拥挤风险和证据边界。

报告不是交易指令，但必须具备研究决策价值，不能只解释为什么不能推荐。

## 4. 新的默认研究流

```text
主题定界
  -> 大胆发散机制
  -> 市场运行图
  -> 具体证券池
  -> 事件/产业场景树
  -> 条件性 setup 排序
  -> 只质证前列候选
  -> Opportunity Brief
```

### 4.1 主题定界

只冻结研究对象、证据截止日、时间窗口和用户要做的判断。不得在开局用复杂逻辑图
和状态预算取代真实搜索。

### 4.2 发散发现

保留 5—7 条有差异的机制路径，至少覆盖直接受益、瓶颈、二阶、替代、失败受益和
预期兑现。假说可以实体无关，但不能被当成具体候选。

### 4.3 市场运行图

每个主题必须回答：

```text
现实事件 -> 市场叙事 -> 预期变化 -> 增量资金 -> 证券载体
        -> 辨识度/流动性 -> 筹码拥挤 -> 事件兑现 -> 二次分化
```

技术成功、题材上涨和公司利润兑现必须分开。

### 4.4 具体证券池

当问题涉及上市公司时，候选必须包含公司名和 ticker。按角色组织，而不是用一个
总分压平：

- `EVENT_BETA`：事件标签和短线资金弹性；
- `ECONOMIC_CAPTURE`：订单、收入或利润承接；
- `BOTTLENECK`：关键材料、部件、设备或服务；
- `SECOND_ORDER`：行业扩张而非单次事件受益；
- `SUBSTITUTE`：主路径失败后的替代路线；
- `FAILURE_HEDGE`：延期、失败或兑现时相对受益；
- `WATCH_ONLY`：有映射，但价格、筹码或证据暂不支持 setup。

找不到上市载体时，必须说明检索覆盖和“无载体”的依据，不能让抽象机制冒充候选。

### 4.5 双轨 setup

- `EVENT_SETUP`：依据题材辨识度、稀缺载体、流动性、相对强弱、筹码和事件窗口；
- `ECONOMIC_SETUP`：依据客户、订单、收入、利润、产能与定价传导。

一只股票可以通过其中一轨而不通过另一轨。条件性排序是研究结论，不等同于买卖指令。

### 4.6 集中质证

只有进入前列的少量候选才进行重型验证。质证必须同时寻找：支持证据、最强替代解释、
成功但股价下跌路径、催化落空路径和更好的替代标的。

## 5. 最小产品对象

新版只保留五类用户有意义的对象：

- `Observation`：带来源和时间的现实变化；
- `Hypothesis`：大胆机制、替代解释和证伪条件；
- `CandidateMapItem`：具体实体、ticker、市场角色、映射和证据边界；
- `ConditionalSetup`：成立场景、触发、时间窗、失效、筹码和风险；
- `OpportunityBrief`：供人判断的最终研究成果。

不为对象复制生命周期状态。用户可见结果只需要：

- `EXPLORE`：值得继续发现；
- `SETUP_READY`：形成条件性机会；
- `NO_USABLE_SETUP`：完成具体标的与市场映射后仍无可用 setup。

## 6. 旧机制处置

### 保留

- URL、来源、日期和 claim 对齐；
- 事实、推断、假说分层；
- 替代解释、证伪条件和 bull/base/bear；
- 时间合同、引用去重、无伪概率；
- 人工掌握执行权。

### 改为按需验证组件

- Crux 对抗；
- Detective/Inquisitor 隔离；
- 候选双边审查；
- 页面快照与精确 claim 核验。

### 退出默认产品合同

- hypothesis 文本自动晋升 OpportunitySeed；
- 抽象候选的 gap task；
- `FORMAL` 作为机会发现成功指标；
- 单一 `ranking_allowed` 对所有具名比较的一刀切；
- `THESIS_CANDIDATE`、`VERIFIED_FOR_HUMAN`、`DRAFT_REQUIRES_HUMAN`；
- Thesis、Decision、Paper Position、订单、仓位、组合和 project handoff。

这些旧对象暂不破坏性删除；先从 SKILL 主入口和默认输出断开，历史运行保持只读。

## 7. 输出合同

Opportunity Brief 的优先顺序：

1. 一句话机会判断；
2. 市场可能如何运行；
3. 具体标的地图；
4. 条件性短线 setup；
5. 产业兑现 setup；
6. 多情景事件树；
7. 触发与失效条件；
8. 事实、推断与假说边界；
9. 最低成本下一验证动作；
10. 证据附录。

运行轮次、状态字段和来源统计只能进入附录，不得占据首屏。

## 8. 朱雀三号验收基准

新版必须满足：

- 不把“筹码拥挤”或“通用检测受益”当作候选名称；
- 涉及 A 股时输出具体公司和 ticker；
- 区分事件弹性与经济承接；
- 分析完整回收、部分成功、失败、延期四条市场路径；
- 输出 1—3 个带触发、失效、拥挤和证据边界的条件性 setup；
- 即使没有高可信长期候选，也解释市场可能如何交易；
- 只有完成具体证券、价格筹码、替代和二阶路径搜索后，才能输出
  `NO_USABLE_SETUP`。

## 9. 工程实施顺序

### Phase 0 — 基准与失败测试

- 本文成为产品基准；
- 建立抽象候选、边界和朱雀案例验收；
- 明确工程通过不等于产品有效。

### Phase 1 — 切断错误主链

- 禁止 hypothesis 自动变 seed；
- 上市证券 seed 强制公司名 + ticker；
- SKILL 主边界止于 Opportunity Brief；
- 下游对象退出默认合同。

### Phase 2 — CandidateMap

- 实现轻量 `CandidateMapItem`；
- 第一轮优先形成具体证券池；
- 增加市场角色、事件/经济 setup、价格和筹码字段。

### Phase 3 — 新 Opportunity Brief

- 首屏改为市场逻辑和具体标的；
- 分开事件与经济排序；
- 审计细节下沉附录；
- 不再用报告等级替代产品价值。

### Phase 4 — 按需验证内核

- 只对前列候选启用重型证据质证；
- 保留支持、反证、定价和 claim 对齐；
- 不产生任何下游业务状态。

### Phase 5 — 回放与清理

- 回放朱雀三号及无机会、错误映射、拥挤兑现案例；
- 评估具体候选覆盖、市场机制和决策可用性；
- 稳定后归档旧默认路径并建立新方法版本。

## 11. 禁止的伪修复

- 新增状态来解释旧状态；
- 再造一个 Candidate 前置对象并复制完整晋级链；
- 用更多 Agent、收据和流程字段代替机会质量；
- 用 `FORMAL`、测试数或引用数冒充研究有效；
- 为了安全禁止所有具体比较；
- 为了召回取消事实与假说标签；
- 强制每个主题凑出股票；
- 顺手建设 Thesis、Decision、交易或组合系统。

本次重置的最终判据不是“旧测试是否都绿”，而是：用户是否获得一个此前没有看到、
逻辑可解释、标的具体、证据边界清楚、可以继续验证或条件性博弈的机会简报。
