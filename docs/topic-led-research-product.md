# Trade Nothing：课题驱动的迭代深度研究产品基准

> 状态：v0.15.0 当前修复基准与验收目标
> 日期：2026-08-10
> 适用入口：`-deepthink2`

## 1. 为什么再次修正产品形态

上一版产品重置纠正了“过早用证据门杀死机会”的问题，但仍把“大胆假说”放在了研究
主轴上。这会产生另一种偏差：系统为了维护假说花园、Landscape 和状态完整性，反而忘了
用户交给它的是一个需要被解释和判断的课题。

真实用户目标不是生成假说，也不是让候选通过流程，而是：

1. 明确这个课题最终需要回答什么；
2. 把复杂课题拆成可以搜索、质证和回答的问题；
3. 每轮解决一部分问题，同时发现原来没意识到的盲点；
4. 根据新答案和新盲点改变下一轮研究重点；
5. 最终形成一份有事实、有机制、有市场判断、有具体载体、有前瞻性并且能给建议的报告。

因此本次修复不是给旧流程再加一个字段，而是重新确定主对象、循环和最终产品。

## 2. 产品宪法

### 2.1 主对象是课题，不是假说或候选状态

运行的根对象是 `Research Agenda`：研究目标、待回答问题、成功回答标准、初始搜索路线。

假说只是一种分析工具。当因果机制存在多种解释时，可以提出机制假说并设计判别检验；
但普通事实题、时间题、产业链题、市场反应题和定价题不应先被改造成“大胆假说”。

### 2.2 每轮既要回答，也要发现新的未知

每轮研究不是“搜到几条 URL”或“给 crux 打一次分”，而是一次问题推进：

```text
选择当前高价值问题
  -> 搜索事实与机制证据
  -> 正面解释与最强反证
  -> 更新答案状态和证据边界
  -> 记录仍缺信息
  -> 提出新盲点和新问题
  -> 重排下一轮优先级
```

新盲点必须说明它可能改变什么：核心结论、市场传导、候选选择、时点、筹码判断、风险或
建议。仅仅“还可以再研究某背景”不构成盲点。

### 2.3 严格性用于校准结论，不用于抑制机会发现

在发现阶段，未完全证实的机制、载体映射和市场路径可以保留，但必须标注为
`HYPOTHESIS` 或 `INFERENCE`。具体候选可以在证据不完整时进入 CandidateMap，只要身份、
作用机制、触发、失效和缺口被诚实表达。

在建议阶段，证据边界必须决定措辞：

- `FACT` 支持明确判断；
- `SINGLE_SOURCE` 支持有保留的判断；
- `INFERENCE` 支持条件性推断；
- `HYPOTHESIS` 支持研究优先级，不足以伪装成已证实结论。

系统不能因为“不够确定”而删掉潜在机会，也不能因为“有想象力”而抹掉证据边界。

`SETUP_READY` 只证明字段完整，不证明值得优先。产业—市场建议还必须通过 Market Bridge：
产业结论形成可证伪的价值转移路径；候选分别进入经济暴露池与市场交易池；在明确时间视野下
与最近替代项比较，并写出当前优先理由和切换条件。

### 2.4 产品止于深度研究报告与建议

本 Skill 范围内的最终产品是 `Deep Research Report`，包括研究结论、条件性建议、市场
运行逻辑、具体标的、事件/产业设置、新盲点、情景树和未决问题。

它不建设或管理 Thesis、Decision、交易、仓位、组合、审批、发布、提醒或跨产品 handoff。
这些流程尚未建设就不进入当前设计。报告可以说“条件性优先关注”，但不能自动生成外部
动作。旧代码里的下游对象仅为兼容，不进入默认产品承诺。

## 3. 主运行对象：Research Agenda

### 3.0 Research Agenda 是控制平面，不是报告 sidecar

对显式 `research_workplan` 的新运行，调度、续研建议和交付时点都由 Agenda 决定：

- 默认只授权一轮；`suggested_max_rounds` 只是旧 crux 审计副轨的安全上限，不是预算；
- 下一轮只选择 `OPEN / PARTIAL / DISPUTED` 问题，`ANSWERED` 永不重派；
- 排序先看是否阻塞当前建议、决策影响、新盲点、答案状态和研究成本，最后才用关联 crux
  做并列项的证据上下文；
- crux 可以承接正式引用和最强质证，但不得覆盖 Agenda 的问题优先级，也不得用
  `MIN_ROUNDS` 或 dry rounds 阻止报告交付；
- 一轮结束后始终可交付完整报告。若仍有低成本高影响问题，系统只返回“建议续研、等待
  授权”，不得自动消耗下一轮。

兼容归档运行仍可沿用旧 crux 控制逻辑，但不得冒充新产品的运行结果。

### 3.0.1 执行真实性不是 Agenda 的新状态

Research Agenda 管“研究什么”；执行真实性合同只管“宿主真的完成了什么”。当前方法的
注册 state、三角色 prompt/payload/宿主收据与 manifest 四者一致，才允许报告写“完成 N 轮”。
否则分别显示 `STATE_ONLY_UNVERIFIED`、`HISTORICAL_REPLAY` 或
`INLINE_DEGRADED_RESEARCH`。这些标签不改变问题状态、研究优先级或结论，只防止运行叙事
污染研究产物。

### 3.1 立题输出

一个新课题必须有 4—8 个初始问题，按需要覆盖：

| 类型 | 要回答的内容 | 示例 |
|---|---|---|
| `FACT` | 当前发生了什么、时间与状态是什么 | 发射窗口是否正式确认，之前为何延期 |
| `CAUSAL` | 结果由什么机制决定 | 回收成败最受发动机、姿态还是海况约束 |
| `MARKET` | 市场会怎样叙事和扩散资金 | 成功后资金先交易整箭、零部件还是卫星 |
| `CANDIDATE` | 哪些具体载体承接事件或经济增量 | 哪家公司是事件 beta，哪家有订单兑现 |
| `PRICING` | 价格和筹码已计入什么 | 回调是否释放预期，前高套牢和换手如何 |
| `RISK` | 什么会让路径失效 | 延期、部分成功或利好兑现分别如何影响 |
| `FORWARD_LOOKING` | 二阶影响和未来结构变化 | 回收验证是否改变发射频次与供应链利润池 |

每个问题包括：

- `question_id`；
- 问题文本；
- 为什么它会改变结论或建议；
- 什么观察算“回答成功”；
- 1—3 个初始搜索路线；
- `decision_impact`、`research_cost` 和 `blocks_current_recommendation`；
- 可选的关联 crux。

### 3.2 逐轮答案账本

问题使用四种真实研究状态：

- `OPEN`：尚未得到可用答案；
- `PARTIAL`：已有一部分答案，但关键环节缺失；
- `ANSWERED`：在当前截止日和研究边界内已经达到成功回答标准；
- `DISPUTED`：正反证据或解释冲突，不能用最后一个 Agent 的文本覆盖争议。

每次更新必须保留：

- 当前答案；
- Detective/Inquisitor 的答案变体；
- 正式绑定证据；
- `FACT / SINGLE_SOURCE / INFERENCE / HYPOTHESIS` 边界；
- 最强质证；
- 尚缺信息；
- 由此产生的下一问题。

没有绑定到同一角色正式 crux 证据的引用不得被洗入 Agenda；但未引证的有效思路仍保留为
推断或假说，不能因为缺引用而被删除。

### 3.3 盲点账本

每个盲点包括：

- 盲点是什么；
- 原来的哪项假设或框架让它被漏掉；
- 它可能改变结论、候选或建议的方式；
- 关联的原问题；
- 最低成本判别检验；
- 首次出现轮次和来源角色。

盲点可以产生新问题并进入下一轮；新问题必须链接一个现有父问题、说明会改变哪项结论或
建议，并给出可判定的成功条件。每轮全局最多接纳两个新问题和两个新盲点；同一父问题已有
活跃派生问题时不得继续分叉。盲点一旦被提升为正式问题，只保留审计可见性，不再重复计作
第二份研究债务。高影响、低成本且会改变当前建议的盲点才有调度优先权。

## 4. Agent 分工

### Framer

把原始课题变成研究目标、Research Agenda、承重研究方向和搜索合同。新运行默认不要求
调用者再维护一套 crux/logic graph；旧引擎需要的结构由兼容审计适配器内部派生且不参与调度。
`thesis_seed` 只是兼容字段，可以写“方向未知的初始看法”。假说花园完全可选；只有用户或
课题确实需要完整机制 Landscape 时，才显式声明 5—7 条路径。

### Detective

寻找能回答当前问题的事实、产业约束、客户/订单/物理流、市场载体和二阶价值转移。
它必须给出问题更新、证据边界、最强反例、新盲点、新问题和 CandidateMap。

### Inquisitor

攻击当前答案而不是机械攻击“多头”。它要区分：答案已被推翻、答案仍有争议、只是缺少
信息，以及替代解释更强。失败路径也要映射替代赢家、失败对冲和被忽视的受益者。

### Judge

只对正式 crux 证据评分，保证收敛控制不被未引证叙述污染。它不评判 Research Agenda
答案、新盲点、假说或 CandidateMap 的“真值”；这些由报告中的证据标签和质证结构表达。

Judge 的 crux 结论只进入审计副轨，不拥有新运行的停止权。停止权属于 Research Agenda：
当前用户问题是否已经可回答，以及是否仍存在能以低成本显著改变答案的下一检验。仅仅存在
未知项、活跃方向或更多可搜索页面都不构成续研理由；同一问题连续两轮没有改善答案状态或
证据边界时，保留为报告限制，但不再自动建议下一轮。

### Parent / Reporter

合并逐题答案和冲突，解释市场机制，比较具体候选，给出条件性研究/市场建议，并把未回答
问题和方法限制放在正文。不得把所有用户价值藏进审计附录。

## 5. 市场机会研究必须回答的链条

```text
事实变化
  -> 哪个产业约束变化、利润池如何转移
  -> 谁有实质经济暴露、何时进入订单/收入/利润/现金
  -> 市场如何命名和理解
  -> 哪类增量资金会参与
  -> 为什么选择某些具体证券作为载体
  -> 价格、流动性和筹码如何放大或压制
  -> 事件结果如何分成成功、部分成功、失败、延期
  -> 产业经济如何通过订单、收入、利润、产能或议价兑现
  -> 哪些二阶路径、替代赢家和失败受益者被忽略
```

技术成功、短线题材强度、公司利润兑现和股价空间是四个不同问题。报告必须分开作答。
产业时钟与市场时钟也必须分开：事件、数周战术、财报季度和长期产业视野不得共享一个静态
股票排序。

## 6. Deep Research Report 产品合同

默认正文结构：

1. 核心结论与条件性建议；
2. 课题、Agenda 和研究进展；
3. 已回答问题、最强质证与尚缺信息；
4. 产业价值转移与分视野市场阶段；
5. 经济暴露池 × 市场交易池、替代比较与条件性优先级；
6. 事件驱动和产业链兑现设置；
7. 新盲点与前瞻推演；
8. 情景、触发、失效、价格与筹码；
9. 未回答问题和下一轮最低成本验证；
10. 证据边界和方法限制。

报告可以明确：

- 条件性优先关注哪个载体；
- 为什么当前时点优先它而不是最近替代标的，以及何时切换；
- 哪个更像短线事件 beta，哪个更像产业利润承接；
- 什么条件下继续观察、放弃或重开研究；
- 当前最重要的未知是什么。

报告不得输出自动交易、仓位、目标收益、未经研究得出的概率或伪确定性排序。

## 7. 朱雀三号类课题验收基准

以“分析朱雀三号遥二回收、延期原因、产业链增量和短线标的”为例，合格产物必须：

1. 把课题拆成成功定义、时间/延期、技术约束、市场传导、产业增量、具体标的、价格筹码、
   失败/部分成功路径和二阶影响等问题；
2. 每轮至少推进当前高价值问题，而不只是新增 URL；
3. 记录“延期本身是否改变筹码和事件窗口”等研究中出现的新盲点；
4. 分开评估发射成功、入轨成功但回收失败、完整回收、再次延期等场景；
5. 给出具体上市公司和 ticker，并区分事件弹性与经济兑现；
6. 分别冻结经济暴露池和市场交易池，说明池的构造规则、成员与证据；
7. 检查回调、相对强弱、换手、套牢或持仓等价格/筹码信息，缺失时明确标注；
8. 给出分时间视野的条件性优先建议、最近替代项、切换条件和放弃条件；
9. 给出最大的产业链利润池变化和前瞻二阶路径；
10. 保留来源、日期、URL 和事实/推断/假说边界；
11. 即使研究未收敛，也交付完整报告，并把未决问题留在正文。

## 8. 反模式

- 把课题强制改写成 5—7 个大胆假说；
- 为了维持状态机完整而增加用户看不见的流程；
- 只验证原始命题，不研究市场会如何运行；
- 用“证据不足”删除具体机会线索；
- 只列公司，不解释资金选择和产业兑现；
- 从任意两只股票开始比较，却没有固定经济暴露池和市场交易池；
- 用一个全局股票顺序覆盖事件、数周、财报和长期产业四种视野；
- 只给审计等级，不给判断与建议；
- 把新盲点无限扩张成没有优先级的研究清单；
- 在当前 Skill 内设计尚未建设的交易或发布流程。

## 9. 工程验收

实现必须通过：

- Research Agenda 初始化、逐轮更新、引用绑定、盲点去重和问题重排单测；
- 统一研究内核的 as-of 日期、证据去重、URL 发布方、顺序无关答案/方向合并单测；
- `ANSWERED` 过滤、盲点改派、Agenda-native stop decision 和显式续研预算单测；
- 无假说花园的机会题可以正常初始化；
- 显式完整 Landscape 仍保留原有覆盖门；
- 默认报告为 `Deep Research Report`，旧 Opportunity Brief 仅显式兼容；
- 报告回放包含答案、质证、新盲点、具体载体、场景和条件性建议；
- 上市标的使用 exchange+ticker 身份；无字段证据、无效窗口或字段冲突不得成为
  `SETUP_READY`；无实际 coverage route 不得声称 `NO_USABLE_SETUP`；
- 探索账本不得改变正式 crux 信号或外部执行边界；
- 一轮已形成条件性建议时，即使旧 crux convergence 仍为 `continue`，报告也必须交付；
- 全量 `make test`、版本一致性和方法身份校验通过。

工程通过只证明合同被实现，不证明真实机会召回率或 Alpha。产品有效性仍需用真实课题
回放，由人盲评“问题覆盖、洞察新颖性、市场解释力、具体性、建议可用性和证据诚实度”。
