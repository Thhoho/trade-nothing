# Trade Nothing v0.18 产品合同

> 日期：2026-08-13；入口：普通问答与 `-deepthink2`

## 目标

主对象是用户的课题，但课题不再被展开成多套持久化控制状态。系统要做的是：找全会改变
判断的当前事实，回答真正承重的问题，解释产业价值如何进入市场，并在证据边界内给出具体、
条件性的载体判断。

严格性用于校准结论，不用于制造流程。最终产品止于深度研究报告与建议。

## 四对象内核

- `TaskSpec` 固定问题、截止日、预算、实体、事实面和问题；
- `EvidenceStore` 保存统一 EvidenceItem 与真实 SourceCheck；
- `DecisionSnapshot` 保存唯一结论、反例、市场桥、标的和未决项；
- `RunLedger` 保存执行、哈希、失败与预算。

Research Agenda 不再是独立控制平面；问题集合属于 TaskSpec，答案属于 DecisionSnapshot。
Current Reality 也不再是一套平行状态；它由强制事实面、SourceCheck 和 material changes 共同
表达。CandidateMap 不再独立存在；具名载体属于按时间视野组织的 Snapshot 字段。

## 每个研究循环

每轮既要回答，也要发现新的未知，但只有能改变判断的未知才值得下一轮：

```text
选择一个 ActionIntent
  -> 核验当前事实或一个承重机制
  -> 更新统一证据
  -> 完整替换 DecisionSnapshot
  -> 校验事实覆盖、语义一致性与执行真实性
  -> 停止，或提出下一项最低成本动作
```

ActionIntent 必须说明可能的目标字段、当前不确定性、所需证据、预期决策变化、停止条件和成本上限。
目标字段只用于编译上下文；验收的是“新观察 + 真实语义 Snapshot 变化”，不是为了满足某个
字段而改写用户结论。
预算是 0–10 轮上限，不是跑满要求；续研必须有明确授权。

## 事实召回验收

上市公司必须先完成官方公告索引枚举。窗口至少覆盖 120 天，并回溯至最近一期定期报告中
更早的日期。系统记录索引条目数，查看完整标题集，并打开所有潜在 HIGH 的财务、经营、
控制、质押、解禁、增减持、融资、诉讼和监管事项。

任何 HIGH EvidenceItem 如果没有进入重大变化、明确缺口或有理由的非重大处置，就阻断
decision-ready。该规则的产品含义是：即使报告写得很好，也不能把已经找到的解禁、接近全部
持股的质押、亿元级增持/融资计划等承重事实丢在证据附件里。

“枚举 80/80”不等于事实召回完成。亏损、减值、关联借款、激励、质押、解禁、担保、诉讼和控制变化等
标题不能用模板理由直接排除，必须打开审阅。

## 产业到市场

产业逻辑与市场博弈使用两条不同链：

```text
事实 -> 约束变化 -> 利润池迁移 -> 公司经济暴露
事件 -> 边际资金 -> 市场交易载体 -> 拥挤/验证/分歧
```

先回答“市场当下在交易哪些载体”，再回答“哪个标的通过条件性研究门”。前者即使没有推荐也可以成立；
后者必须同时绑定价值路径、同时间视野的市场状态、产业暴露证据和市场证据，
并给出最近替代、切换条件、触发、失效以及价格/拥挤边界。字段完整不自动产生推荐。

## 质证

Lead 自我反例永远明确标为自我反例。只有在具名承重结论可能被推翻且预算仍在时，才调用 Targeted
Challenger。在 Codex 中默认使用一个原生子智能体；CLI 模型进程只是显式选择的可选适配器。它只交付攻击包，
不能写 Snapshot。Lead 随后接受、部分接受、拒绝或保留未决。

报告必须区分“原生子上下文已报告隔离”、“外部进程已证明”和“父 Agent 自报”；不得用一个
`VERIFIED` 掩盖三者的差异。

Judge 不再属于活跃架构；确定性校验替代结构裁判，语义解决仍由唯一 Lead 承担。

## Deep Research Report 产品合同

报告必须直接从 Snapshot 纯渲染：

1. 核心判断与边界；
2. Current Reality、重大变化和重大缺口；
3. 每个 TaskSpec 问题的答案与自我反例；
4. 价值转移路径与分时间视野市场运行；
5. 具体标的、最近替代、触发、切换和失效；
6. Challenger 质证、完整执行来源及 Lead 处理；宿主报告不冒充独立性强证明；
7. 未决问题与最低成本下一验证；
8. Evidence Ledger 和执行真实性。

一轮结束后始终可交付完整报告，仅当已经存在 Lead Snapshot；运行失败时明确降级，不自动
重试，也不把技术成功写成 Alpha 或正式推荐。用户版和审计版来自同一 Snapshot，由报告 bundle
绑定；交付时禁止手工补一段“更正结论”。

## 朱雀三号类课题验收基准

同模型、同截止日、可比预算盲测时，应同时检查：官方状态与时间边界、工程事实与经济暴露
的分离、事件交易与季度兑现的分离、具名 A 股载体的真实关联、最近替代和切换条件、失败路径、
遗漏的近期重大事实，以及成本。流程正确而用户判断没有变好，仍然判定产品失败。
